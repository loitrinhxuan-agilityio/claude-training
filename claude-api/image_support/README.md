# Practice: Image support

Companion to the lesson
[Image support](https://academy.claude.com/courses/building-with-the-claude-api/image-support)
(*Building with the Claude API*, lesson 40).

## What the lesson covers

- Send an `image` block next to a `text` block in a user message (base64, or a URL).
- Limits: up to 100 images per request, 5MB each, max 8000px (one image) or 2000px
  (multiple images). Cost: about `(width x height) / 750` tokens per image.
- Image prompts need the same care as text prompts. "How many marbles?" can be
  wrong; a step-by-step method, a one-shot example, or splitting the task helps.

## Files

| File | Purpose |
|---|---|
| `images/marbles_14.png`, `images/marbles_23.png` | 640x480 test images with a **known** marble count (14 and 23), so accuracy can be scored. They were generated by a one-off script that is not kept in the repo |
| `practice.py` | Part 1 describe an image, Part 2 token cost, Part 3 compare three counting prompts |

```bash
uv run python image_support/practice.py              # everything, 3 trials per prompt
uv run python image_support/practice.py --trials 5
uv run python image_support/practice.py --image photo.jpg --ask "What is in this photo?"
uv run python image_support/practice.py --url https://example.com/photo.jpg   # URL image block (untested)
```

## What I observed (`claude-haiku-4-5`, true answer 23, 5 trials per prompt, two separate runs)

| prompt | run 1 answers | run 1 mean abs error | run 2 answers | run 2 mean abs error |
|---|---|---|---|---|
| naive: "How many marbles are in this image?" | 30,30,30,30,30 | 7.0 | 30,30,30,30,25 | 6.0 |
| step-by-step (the lesson's prompt) | 29,28,23,25,25 | 3.0 | 23,29,30,29,30 | 5.2 |
| one-shot (a 14-marble example first) | 24,24,20,21,24 | 1.6 | 22,24,24,24,24 | 1.0 |

- The naive prompt is confidently wrong: it said 30 almost every time.
- **One-shot was closest in both runs** and never exactly right (it landed on 24, one over).
- **Step-by-step did not reliably beat naive here.** It helped in run 1 and barely helped in
  run 2, and its answers vary a lot. The lesson presents it as an improvement; on this
  image with this small model, the evidence is mixed. That is one image and 10 trials per
  prompt, so it is not a refutation.
- **Token estimate:** the 640x480 image is estimated at 410 tokens; the API reported 427
  input tokens in total, so `(w x h) / 750` is a good approximation (the small difference
  includes the text).
- Exact match is a harsh metric for counting, so the script also reports mean absolute error.

## Things to know

- The answer is parsed as the last whole number in the reply, a heuristic. I checked a
  naive and a step-by-step reply by hand and it parsed correctly, but a reply that ends
  with an unrelated number would be misread.
- Part 3 spends real API calls (about 15 with the defaults). Parts 1 and 2 are 2 calls.

## Exercises

1. Run with `--trials 10`. Does the step-by-step vs naive gap become clear or stay noisy?
2. Edit `STEP_BY_STEP` (for example, count by color, or divide the image into four
   quadrants and count each). Do the answers get closer to 23?
3. Add a harder target image with more marbles (drawn or photographed, count it yourself),
   put it in `images/`, and update the true answer (`truth`) in `practice.py`.
   Do all three prompts degrade as the count rises?
4. Send both marble images in one request and ask which has more marbles. Note the
   2000px limit when you send several images.
5. Try a bigger model (change `MODEL`). Does the naive prompt improve enough to make the
   prompt technique unnecessary?
6. Use `--image` with a real photo of your own, and write a structured prompt like the
   lesson's fire-risk example (numbered steps, a rating scale, one sentence per step).
